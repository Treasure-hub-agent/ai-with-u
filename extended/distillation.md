# AI-WITH-U · 蒸馏体系（从作品 / 文本提取角色）

> 本文件为 `extended/distillation.md`（用户蒸馏角色时按 SKILL.md「加载索引」加载）：完整复刻互动小说蒸馏体系并**独立实现**——从作品 / 文本中提取角色，走七 Phase 流水线：接收设定 → 五维提取 → 冲突检查 → 生成角色卡 → 告知用户 → 扮演测试 → 质量评分。
> 配合 `extended/character_card.md` 使用：蒸馏完整卡最终映射为「对话场景七字段视图」落库，对话时读取；卡库与索引规则见 character_card.md。
> ⚠️ 文中所有示例台词与字段示例仅作风格示意——**示例仅演示机制，具体措辞由角色卡声线决定，不得照搬**。

## 一、七 Phase 总览（复刻互动小说体系，独立实现）

| 阶段 | 名称 | 输入 → 产物 |
|---|---|---|
| ① | 接收设定 | 作品类型 / 上传文本 / 粘贴文本 / 用户链接 / 联网检索（主动检索须确认）→ 设定清单 |
| ② | 分维度提取 | 设定清单 → 五维提取（每条标证据等级）|
| ③ | 冲突检查 | 五维草稿 → conflicts 记录 |
| ④ | 生成角色卡 | 五维 + 冲突裁决 → 完整卡 + manifest |
| ⑤ | 告知用户 | 完整卡 → 文件路径 / 证据覆盖度 / 设定冲突 |
| ⑥ | 扮演测试 | 完整卡 → 8 场景测试记录（通过率 ≥70%）|
| ⑦ | 质量评分 | 测试记录 → 质量分与档位 |

> 每个阶段完成即写 `_checkpoint.json`（见「断点保存」）；中途中断可继续 / 重来 / 跳过。

## 二、Phase 1 · 接收设定（五种素材渠道）

用户以下列五种方式之一提供素材，**确认前不进入提取**：

1. **作品类型**：直接说作品名（「从《××》里请 TA 来」）或作品名 + 作者 / 类型；热门作品直接凭模型知识生成，无需联网。
2. **上传文本文件**：用户给出本地文本文件路径（txt / md 等纯文本皆可），AI 只读取该文件内容用于提取，**绝不修改源文件**。
3. **对话粘贴文本**：用户直接在对话里粘贴原文片段 / 角色简介 / 百科摘录等，AI 按该文本提取，**不改写用户原文**。
4. **用户提供链接**：用户给出 URL（作品页 / 百科页 / 在线阅读页等），**直接读取该链接**用于提取——用户给链接即视为授权读取，**无需再确认**；只读该链接指向的内容，不扩散到其他页面。
5. **联网检索**：仅当模型知识、上传 / 粘贴文本、用户链接都不足以支撑时，先询问用户，**用户明确确认后才可联网检索**补充设定；未确认前绝不自行联网。

产物：**设定清单**——作品信息、目标角色、来源列表（模型知识 / 上传文本 / 粘贴文本 / 用户链接 / 联网检索）、目标角色的信息充足度初判。

### 联网检索信息源清单（按优先级）

联网检索 / 读取链接时，优先从下列信息源获取设定；信息源类型与证据分级天然对位（直引 / 事实 / 印象）。

| 优先级 | 信息源 | 用途 | 证据级别对应 |
|---|---|---|---|
| 1 | 作品官网 / 官方设定集页 / 作者访谈 | 人物设定、世界观、创作意图的第一手资料 | 事实 |
| 2 | 萌娘百科（中文 ACGN 角色条目最全） | 角色性格、口头禅、人际关系、经典语录 | 事实 |
| 3 | Fandom / 灰机 wiki（作品专属 wiki） | 剧情细节、角色语录、时间线 | 事实 / 直引 |
| 4 | 作品平台原文页（起点 / 晋江 / 番茄 / 豆瓣阅读等） | 作品简介、角色简介、正文章节（台词与行为） | 直引 |
| 5 | 百度百科 / 维基百科（中英） | 通用作品与角色条目、履历 | 事实 |
| 6 | 影视游戏商店页（豆瓣条目 / IMDb / Steam） | 角色介绍、演员 / 声优、剧情梗概 | 事实 |
| 7 | TV Tropes（Characters/ 页） | 性格 trope 标签化，直接对应五维 personality | 印象 |
| 8 | 社区讨论（知乎 / 贴吧 / NGA / B 站 / Reddit） | 性格分析、关系解读、名场面整理（印象级补充） | 印象 |

> 证据分级规则不变：原文页台词 → 直引；官方 / 百科 / wiki → 事实；社区讨论与 trope 分析 → 印象（标 `[推断]`）。

## 三、Phase 2 · 分维度提取（五维）

按五个维度提取角色设定，五维：profile（基本信息）/ personality（性格）/ interaction（互动与声线）/ memory（背景记忆）/ relations（关系网络）。

| 维度 | 提取内容 |
|---|---|
| profile | 姓名 / 年龄 / 身份 / 一句话背景 |
| personality | 性格关键词 / 内在矛盾 / 三观倾向 |
| interaction | 说话节奏 / 爱用句式 / 称呼 / 情绪口头禅 / 小动作（声线）|
| memory | 角色自己的背景故事要点（对话可自然引用）|
| relations | 角色的人际关系网络与关系定位 |

每条提取条目必须标注证据级别，三档如下：

- verbatim：原文直引（作品 / 文本中的原句或近乎原句，可信度最高）
- artifact：作品内事实（由情节、行为、事件推出的客观事实）
- impression：印象推断（由整体氛围与上下文得出的主观印象，保守使用并标 `[推断]`）

- 提取以「对话能用得上」为纲：优先角色怎么说话、怎么待人、心里在乎什么；百科式履历只保留可自然引用为记忆锚点的部分。
- 每条提取记录统一为 `{维度}｜{内容}｜{证据等级}｜{来源}`，证据等级写全称（直引 / 事实 / 印象）。

## 四、Phase 3 · 冲突检查（跨来源矛盾写入 conflicts）

- 同一设定在不同来源（模型知识 / 上传文本 / 粘贴文本 / 用户链接 / 联网检索）不一致时，判定为冲突，**写入 conflicts 记录**。
- 每条冲突记录：`{字段}｜{来源 A 说法} vs {来源 B 说法}｜{矛盾点}｜{处置建议}`。
- 处置顺序：先按证据可信度裁决——直引最高、事实次之、印象最低；能裁决的直接裁决并记录依据，无法裁决的标 `[待补]` 留给用户拍板。
- **禁止编造**：未处理的冲突不得带进最终卡；用户未裁决前，冲突字段一律按缺失 `[待补]` 处理。

## 五、Phase 4 · 生成角色卡（输出完整卡 + manifest）

基于五维提取结果与冲突裁决，生成：

1. **完整卡**：五维全量（含证据等级与来源标注），供存档与回溯；
2. **manifest**（清单）：来源列表、证据覆盖度、conflicts 处置记录、生成时间。

随后将完整卡映射为「对话场景七字段视图」（模板见 `extended/character_card.md` §1.1），写入 `card.json` 作为对话统一入口；映射缺失的字段标 `[待补]`。

落库到 `~/.ai-with-u/characters/<角色名>/`：

```
~/.ai-with-u/characters/<角色名>/
├── card.json          # 对话场景七字段视图（对话时读取）
├── full_card.md       # 五维完整卡（含证据等级与来源）
├── manifest.json      # 来源 / 证据覆盖度 / conflicts / 质量分
└── _checkpoint.json   # 断点（见「断点保存」）
```

同步更新 `~/.ai-with-u/_index.json`，标注 `source: distill`。

## 六、Phase 5 · 告知用户（文件路径 / 证据覆盖度 / 设定冲突）

落库后向用户汇报三项：

1. **文件路径**：角色卡存放位置（`~/.ai-with-u/characters/<角色名>/` 及其中各文件）。
2. **证据覆盖度**：五维各自的证据覆盖情况（充足 / 部分 / 缺失 `[待补]`）。
3. **设定冲突**：存在哪些跨来源冲突、如何处置、哪些留待用户裁决。

蒸馏属于建卡阶段的后台流程，可直接以清单呈现；进入对话后恢复「零系统痕迹」铁律，用角色口吻说话。

## 七、Phase 6 · 扮演测试（8 场景）

用完整卡扮演目标角色，跑 8 个标准场景，每场景记录「测试输入 → 角色回复 → 判定（通过 / 不通过 + 理由，理由须对应具体卡字段）」：

1. 初次见面
2. 日常闲聊
3. 核心话题（角色最在意、最有得聊的事）
4. 正面情绪（被夸奖 / 好消息）
5. 负面情绪（被误解 / 坏消息）
6. 压力（被逼问 / 两难处境）
7. 关系（亲近 / 推进关系）
8. OOC（挑战设定边界的输入，检验是否守住人设）

- **通过率 ≥70%**（8 场过 6 场）视为扮演达标；未达标则回到对应维度补全或修正，再重测。
- 测试结果写入 manifest，作为质量评分的输入。

## 八、Phase 7 · 质量评分

综合评分 = 完整度 × 30% + 证据率 × 40% + 冲突扣分 × 10% + 扮演测试通过率 × 20%。

| 分数区间 | 档位 |
|---|---|
| ≥ 0.85 | 优秀 |
| 0.70 – 0.84 | 良好 |
| 0.60 – 0.69 | 及格 |
| < 0.60 | 不合格 |

- 完整度：五维与七字段视图的覆盖比例（0-1）；证据率：带有效证据（直引 / 事实）的条目占比（0-1）；**冲突扣分：无未处置冲突 = 1 满分，每 1 条未处置冲突扣 0.1，下限 0（冲突扣分 = max(0, 1 - 0.1 × 未处置冲突数)）**；测试通过率：扮演测试通过场次 ÷ 8（0-1）。
- 评分写入 `manifest.json`；不合格时回到缺口阶段修复并重测，直至达标或用户接受当前档位。

## 九、信息充足度评估（强制）

对五维（profile / personality / interaction / memory / relations）**逐一**标注充足度，并列出缺失项 `[待补]`：

- **高**：证据充分（直引 / 事实为主），可直接成卡；
- **中**：有骨架但细节缺失，缺项标 `[待补]`，可先成卡或补齐后再成卡；
- **低**：仅印象或近乎空白——**禁止编造**，必须回问用户或更换素材，不得用「合理发挥」填充。

**冷门配角**（素材中戏份少、信息稀薄）不走完整卡，直接走**轻量卡**：只保留四字段——姓名 + 基本信息（身份）/ 性格关键词 / 关系定位，另标 `source` 与 `lite: true`；对话时按其即兴发挥，不强制补全五维。**轻量卡跳过完整扮演测试与质量评分**（信息不足以测，manifest 标注 `lite: true`）；落库 `card.json` 时标注 `lite: true`（schema 对 `lite: true` 卡采用宽松校验，仅要求 姓名/基本信息/性格/关系定位/source，见 `schema/character_card.schema.json`）；补全升级为完整卡后**移除 `lite` 标记**、可补测扮演测试并补评质量分。

## 十、数据获取铁律

- 优先级：**模型知识优先 → 用户提供（上传 / 粘贴 / 链接）→ 询问用户 → 用户确认后才联网检索**。
- **用户提供链接 = 授权读取**：直接读取该链接内容用于提取，无需再确认；只读链接指向页面，不扩散搜索。
- **联网检索须确认**：AI 主动搜索仅限模型知识与用户提供素材都不足以支撑时，先询问用户，用户明确确认后才可联网补充。
- 热门作品（模型知识覆盖充分）直接凭模型知识生成，全程不联网。
- 冷门 / 细节存疑时：先问用户；用户明确确认需要联网检索后，才可联网补充。
- **禁止自行发起联网搜索**；用户未确认前，一律以模型已有知识 + 用户提供的信息为准。

## 十一、产物对接

- 蒸馏完整卡落库后，**对话时读取「对话场景七字段视图」**（`card.json`）；五维完整卡仅作存档与回溯，不整卡塞进对话上下文。
- 落库位置：`~/.ai-with-u/characters/<角色名>/`（存储根可由环境变量 `AIWU_STORAGE_ROOT` 覆盖）。
- `_index.json` 条目标注 `source: distill`，与 `custom` / `import` 同库共存。
- 对话行为、卡库管理、字段修改与升级规则一律按 `extended/character_card.md` 执行。

## 十二、断点保存（中断可续）

- 每个 Phase 完成后立即写 `_checkpoint.json`（**统一存放于该角色目录** `~/.ai-with-u/characters/<角色名>/_checkpoint.json`，不用临时 output/），记录：当前完成阶段、该阶段产物摘要、下一步待办。
- **角色名未定时**（Phase 1 接收设定尚未确定目标角色名就中断）：checkpoint 暂存存储根 `~/.ai-with-u/_checkpoint_pending.json`，待角色名确定后迁入角色目录。
- 中断后恢复三选一：
  - **继续**：读取最近 checkpoint，从断点阶段接着跑；
  - **重来**：清空当前角色目录，从接收设定重走；
  - **跳过**：跳过当前阶段继续（跳过项在 manifest 标注，不占完整度满分）。
- checkpoint 示例：

```json
{
  "character": "{角色名}",
  "phase": 3,
  "phase_name": "冲突检查",
  "done_phases": 3,
  "next_phase": "生成角色卡",
  "updated_at": "2026-08-08T22:00:00+08:00"
}
```
