# AI-WITH-U · 会话接续与时间差感知

> 本文件为 `extended/session_continuity.md`（按需加载）：定义 **session.json 字段与结构**、**滚动摘要机制**、**last_ts 规则**、**开局单页选择阶段**、**时间差感知实现**与**全新开始/彻底重置**。
> 加载时机：开局选中已有角色、新会话接续、需要时间差感知开场、用户要求「全新开始/彻底重置」时，按 SKILL.md「加载索引」路由加载。
> 与 `extended/diary_memory.md` 配合：session.json 管最近 3-5 轮滚动摘要（工作记忆），更早记忆沉睡在 diary.md（长期记忆）；本文件只描述会话侧机制。

## 一、session.json 字段

- 路径：`{存储根}/characters/<角色名>/session.json`（存储根默认 `~/.ai-with-u/`，见 `extended/run_config.md` 五）
- 每轮对话随写盘更新，是「新会话接续 + 时间差感知」的文件侧依据

| 字段 | 类型 | 说明 |
|---|---|---|
| `recent` | array | 最近 3-5 轮对话摘要（滚动窗口，超出的并入日记） |
| `mood` | string | 当前情绪（如：放松 / 低落 / 开心） |
| `topic` | string | 未竟话题（上次没聊完的事、未到期的约定与待办，如「下周三考试」；事办完或过期即更新） |
| `mode` | string | 交互模式：`text`（纯文本）/ `text+action`（文本+动作，默认） |
| `last_ts` | string | 上次互动时间戳（ISO 8601，如 2026-08-08T22:30:00+08:00） |
| `turn_count` | integer | 累计对话轮次（仅对话轮 +1，展示/查询类指令如看看日记/角色卡/关系不计数；跨会话持久化；供日记「每满 10 轮自检」计数） |

示例：

```json
{
  "recent": [
    "TA 说周五有考试，压力很大",
    "约好考完一起去吃火锅"
  ],
  "mood": "放松",
  "topic": "周五考试",
  "mode": "text+action",
  "turn_count": 12,
  "last_ts": "2026-08-08T22:30:00+08:00"
}
```

- **亲密度 = 模型现算的即时判断（非数值、不落盘）**：档位沿用五档（陌生 / 认识 / 熟悉 / 亲近 / 亲密），由模型**每次读取日记与近况综合判断**得出——**不写回 session.json、不存任何档位字段、无轮次刻度、无升档映射表、无进度条**。**起点档由卡内「关系定位 / 你的身份」锚定**：设定本来就是夫妻、恋人、旧识、姐弟的，起点就该落在对应的档上（亲近 / 亲密 / 熟悉…），**只有设定确为陌生人时起点才是「陌生」**。判断信号（关系进展事件清单）见 `extended/diary_memory.md` 三「必记类」，但信号只供模型判断，**不触发写盘**
- **展示位置**：只在**功能界面**（主菜单 / 角色簿 / 单页选择 / 「关系」指令）以**非数值档位标签**呈现（如 `{角色名}（认识）`）；**聊天轮次内零亲密度表述**（不说「亲密度提升 / 好感度 +1 / 你们的亲密度是 X 级」），符合 SKILL.md 铁律 #0 的功能界面例外口径
- **「关系」指令**：以角色口吻说出你们现在的档位（自然语言、非数值），查看时现算，**不写回、不落盘**
- **旧数据**：历史 `session.json` 里若存在旧版遗留的 `intimacy` 字段，**不读、不写、不主动删除**（留着无影响）

## 二、滚动摘要机制（控 token，防「迷失在中间」）

- `recent` 只保留**最近 3-5 轮**对话细节（滚动窗口）；超过窗口的细节不留在 session，而是**并入 diary.md** 沉睡
- 更早记忆默认**不参与每轮上下文**——仅在**接续开场**、**相关话题被用户显式提及**、或触发「看看日记」时读取 diary.md（读取顺序与召回优先级见 `extended/diary_memory.md` 四）；平时全量塞入上下文会浪费 token，且模型易「迷失在中间」（只记得开头与结尾、中间失真）
- 角色靠摘要保持近期连贯，靠日记保持长期一致；两者口径冲突时以日记为准（记忆唯一权威源，见 `extended/diary_memory.md`）

## 三、last_ts 规则（以文件为准）

- **每轮写盘同步更新**：每轮对话写入 session.json 时，`last_ts` 同步更新为当前时间
- **跨客户端/多设备一律以文件 last_ts 为准**，不依赖本会话上下文——用户在 Hermes 聊完换 Cursor/Claude Code，时间差感知仍一致；读取 session 时以文件状态为权威（`last_ts`、`recent` / `topic` 摘要均读文件）
- 时间来源：AI 优先从环境获取真实当前时间；获取不到时降级为按用户消息内容/上下文推断，不硬猜时段
- **时区**：`last_ts` 与当前时间的比较一律以**用户本地时区**为准（`last_ts` 写盘保留 UTC 偏移，如 `+08:00`；换算方式见 `extended/run_config.md` 四）
- **并发写**：同一时刻只用一个客户端；交替使用客户端时的最小合并规则见 `extended/run_config.md` 五
- **降级期承载**：文件不可写期间会话状态照常按上下文推进；待写入条目与待执行指令的留存与恢复后补写口径见 `extended/run_config.md` 三
- 文件读写失败 → 静默降级纯上下文模式，对话不中断、下轮重试（见 `extended/run_config.md`）

## 四、开局单页选择阶段

选中角色后，检测该角色有无历史内容（`{存储根}/characters/<角色名>/` 下 session.json 的 `recent`/`topic`、diary.md 是否有条目），按**三态**决定开局方式（判定只看文件内容，与「是否刚重置过」无关）：

| 状态 | 判定 | 开局行为 |
|---|---|---|
| 无历史档案 | `recent`/`topic` 均空 **且** diary 无条目（从未聊过，或彻底重置后） | 直接开始首次对话（首条消息即卡内 `opening`；卡内没有时即时生成并写入，见 `extended/character_card.md` 2.5），不经选择阶段 |
| 全新开始之后 | `recent`/`topic` 均空，**但 diary 有条目** | 不经选择阶段、**不读 `opening`**（它是「初次见面」的用语，与「TA 还记得你这个人」矛盾）：按 diary 记忆 + 时间差感知自然开场 |
| 有历史档案 | `recent`/`topic` 至少一项非空 | 单页选择阶段（见下） |

```
选中角色
 ├─ 无历史档案 / 全新开始之后 → 直接开始对话（登场前先出一行状态条，首条消息按上表口径生成，不经选择阶段）
 └─ 有历史档案 → 单页选择阶段（页首同样带一行状态条）：
      ① 默认首选：「继续与XXX的故事」——可直接一键开始
         （开场前先读 session.json 的 `recent` / `topic`，再看 diary.md 里未竟话题命中段与「在推进」条目，
           读取顺序见 `extended/diary_memory.md` 四；首条消息即角色按时间差感知生成的开场白，
           到期约定与生日纪念日一并自然体现）
      ② 轻量次项：「全新开始」/「查看/修改角色卡」
      ③ 确认开始：「继续」可跳过确认直接进对话
```

- **交互模式不再出现在开局界面**：skill **默认文本+动作**（`text+action`）；想用纯文本是**建卡时的可选项**（见 `extended/quick_create.md`），随时也可用「切换纯文本 / 切换动作」改
- 状态条格式与简介规则见 `extended/character_card.md` §2.2

- 设计取舍：保留**单页选择阶段**（继续为默认首选、可一键跳过确认），**交互模式移出开局界面**（skill 默认文本+动作，纯文本改为建卡时可选项）——不叠多层菜单

## 五、时间差感知实现（双信号）

- 每轮回复前（尤其接续开场时）按 `last_ts` 与当前时间判断「距上次对话隔了多久」，用语气和开场内容自然体现；**绝不输出「检测到间隔 X 小时」类系统表述**
- 档位判定（间隔五档 / 时段变化 / 同夜长间隔例外）、档位边界与优先级见 SKILL.md「🔴 时间差感知（双信号）」——P0 常驻已含判定表，本文件不重复
- 本文件负责 `last_ts` 的写盘时机与跨客户端读取规则（见 §三）：时间差判断的数据来源是文件里的 `last_ts`

## 六、全新开始 / 彻底重置

| 操作 | 清空范围 | 结果 |
|---|---|---|
| 全新开始 | 会话状态（session.json：`recent` / `mood` / `topic` / `turn_count` 归零，`last_ts` 重置为当前时间；**`mode` 交互模式保留**；亲密度为模型现算、不落盘，无需保留） | 对话记忆归零；**日记默认保留**——角色还是「记得你这个人」，只是不记得最近聊了什么 |
| 彻底重置 | 会话状态 + **diary.md 全部清空** | 一切归零，等同从未认识 |

- 默认只提供「全新开始」；「彻底重置」为显式二次确认操作（用户明确要求才执行），防误删长期记忆
- 重置后不再经单页选择，直接开始对话——**按 §四 三态判定**：彻底重置（连 diary 也空）→ 无历史档案，首条消息用卡内 `opening`；仅「全新开始」（`recent`/`topic` 归零、diary 保留）→ **跳过 `opening`**，按日记记忆 + 时间差感知自然开场
- 全文零系统痕迹；确认语口径见 `references/command_nav.md` 执行纪律
