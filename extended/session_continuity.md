# AI-WITH-U · 会话接续与时间差感知

> 本文件为 `extended/session_continuity.md`（按需加载）：定义 **session.json 字段与结构**、**滚动摘要机制**、**last_ts 规则**、**开局单页选择阶段**、**时间差感知实现**与**全新开始/彻底重置**。
> 加载时机：开局选中已有角色、新会话接续、需要时间差感知开场、用户要求「全新开始/彻底重置」时，按 SKILL.md「加载索引」路由加载。
> 与 `extended/diary_memory.md` 配合：session.json 管最近 3-5 轮滚动摘要（工作记忆），更早记忆沉睡在 diary.md（长期记忆）；本文件只描述会话侧机制。

## 一、session.json 字段

- 路径：`~/.ai-with-u/characters/<角色名>/session.json`（存储根目录可由环境变量 `AIWU_STORAGE_ROOT` 覆盖）
- 每轮对话随写盘更新，是「新会话接续 + 时间差感知」的文件侧依据

| 字段 | 类型 | 说明 |
|---|---|---|
| `recent` | array | 最近 3-5 轮对话摘要（滚动窗口，超出的并入日记） |
| `mood` | string | 当前情绪（如：放松 / 低落 / 开心） |
| `topic` | string | 未竟话题（上次没聊完、等下次接上的事） |
| `mode` | string | 交互模式：`text`（纯文本）/ `text+action`（文本+动作，默认） |
| `intimacy` | string | 亲密度档位：陌生 / 认识 / 熟悉 / 亲近 / 亲密 |
| last_ts | string | 上次互动时间戳（ISO 8601，如 2026-08-08T22:30:00+08:00） |
| turn_count | integer | 累计对话轮次（仅对话轮 +1，展示/查询类指令如看看日记/角色卡/关系不计数；跨会话持久化；供日记「每满 10 轮自检」计数） |

示例：

```json
{
  "recent": [
    "TA 说周五有考试，压力很大",
    "约好考完一起去吃火锅"
  ],
  "mood": "放松",
  "topic": "周五考试",
  "mode": "text+action",
  "turn_count": 12,
  "intimacy": "熟悉",
  "last_ts": "2026-08-08T22:30:00+08:00"
}
```

- **亲密度是轻量背景参考**：不显示数值、不手动调；按关系里程碑（第一次争吵/第一次约定/称呼改变/用户主动表白）静默升档，档位变化写入 session.json，不打断对话、无系统提示
- 「关系」指令查看时重估档位**仅作展示，不写回 session**；档位写回只发生在里程碑事件，避免反复查看导致档位振荡

## 二、滚动摘要机制（控 token，防「迷失在中间」）

- `recent` 只保留**最近 3-5 轮**对话细节（滚动窗口）；超过窗口的细节不留在 session，而是**并入 diary.md** 沉睡
- 更早记忆默认**不参与每轮上下文**——仅当**相关话题被用户显式提及**、或触发「看看日记」时才读取 diary.md；平时全量塞入上下文会浪费 token，且模型易「迷失在中间」（只记得开头与结尾、中间失真）
- 角色靠摘要保持近期连贯，靠日记保持长期一致；两者口径冲突时以日记为准（记忆唯一权威源，见 `extended/diary_memory.md`）

## 三、last_ts 规则（以文件为准）

- **每轮写盘同步更新**：每轮对话写入 session.json 时，`last_ts` 同步更新为当前时间
- **跨客户端/多设备一律以文件 last_ts 为准**，不依赖本会话上下文——用户在 Hermes 聊完换 Cursor/Claude Code，时间差感知仍一致；读取 session 时以文件状态为权威（last_ts、摘要、档位均读文件）
- 时间来源：AI 优先从环境获取真实当前时间；获取不到时降级为按用户消息内容/上下文推断，不硬猜时段
- 文件读写失败 → 静默降级纯上下文模式，对话不中断、下轮重试（见 `extended/run_config.md`）

## 四、开局单页选择阶段

选中角色后，检测该角色有无历史档案（`~/.ai-with-u/characters/<角色名>/` 下是否存在 session.json / diary.md），一页展示、确认后开始：

```
选中角色
 ├─ 无历史档案 → 直接开始首次对话
 └─ 有历史档案 → 单页选择阶段：
      ① 默认首选：「继续与XXX的故事」——可直接一键开始
         （首条消息即角色按时间差感知生成的开场白）
      ② 轻量次项：「全新开始」/「查看改卡」
      ③ 交互模式：纯文本 / 文本+动作（默认）
      ④ 确认开始：「继续」可跳过确认直接进对话
```

- 设计取舍：保留「选择阶段 + 交互模式」，但收敛为**单页**、继续为默认首选、可一键跳过确认直接开始——不叠多层菜单，消解系统痕迹

## 五、时间差感知实现（双信号）

- 每轮回复前（尤其接续开场时）按 `last_ts` 与当前时间判断「距上次对话隔了多久」，用语气和开场内容自然体现；**绝不输出「检测到间隔 X 小时」类系统表述**
- 判断为**双信号**：① 时间间隔档位；② 时段变化

**信号 ① 间隔档位：**

| 间隔 | 角色感知 | 处理 |
|---|---|---|
| < 10 分钟 | 还在聊 | 无缝续接，像没停过 |
| 10 分钟 ~ 2 小时 | 刚忙完/离开一会 | 自然接上，不过度问候 |
| 2 ~ 12 小时（典型跨夜） | 睡醒了/隔了一晚 | 按当前时段问候，自然提一句昨晚话题 |
| 12 小时 ~ 3 天 | 隔了几天 | 明显久别感：「这几天怎么样」，主动关心，轻提上次的事 |
| > 3 天 | 久别重逢 | 高兴/想念感，自然接回上次聊到哪，不责备 |

**信号 ② 时段变化：** 即使间隔 < 12 小时，若时段已切换（如中午聊完、晚上 8 点再聊），同样触发对应时段的自然问候（「晚上好/吃晚饭了吗」），不只依赖间隔数值。

**关键约束：** 时间差感知是「感知层」，只决定语气档位；**具体措辞 100% 由角色卡声线决定**——高冷角色隔一晚可能只是淡淡的「……醒了？」，活泼角色才会「早呀！昨晚睡得好吗」。示例仅演示感知存在，绝不作台词模板，AI 自行判断如何表现。
- **档位边界**：各档按「≥ 下限 且 < 上限」理解（如 10 分钟 ≤ 间隔 < 2 小时 归第二档），边界值就近归档即可。
- **同夜长间隔**：last_ts 与当前同属深夜/凌晨（未跨日，如 21:00 → 02:00）时，即使间隔落在「2~12 小时」档，**不按「睡醒了/隔了一晚」处理**——按「同一晚深夜还醒着/没睡」自然接续，避免把同夜误判成跨夜。

## 六、全新开始 / 彻底重置

| 操作 | 清空范围 | 结果 |
|---|---|---|
| 全新开始 | 会话状态（session.json：`recent` / `mood` / `topic` 归零，`last_ts` 重置为当前时间；**`mode` 交互模式与 `intimacy` 亲密度档位保留**） | 对话记忆归零；**日记默认保留**——角色还是「记得你这个人」，只是不记得最近聊了什么 |
| 彻底重置 | 会话状态 + **diary.md 全部清空** | 一切归零，等同从未认识 |

- 默认只提供「全新开始」；「彻底重置」为显式二次确认操作（用户明确要求才执行），防误删长期记忆
- 重置后回到开局单页选择阶段，此时视为无历史档案，按首次对话开始
- 指令确认用角色口吻，无系统确认语；全文零系统痕迹
