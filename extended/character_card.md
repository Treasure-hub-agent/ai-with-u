# AI-WITH-U · 角色卡体系（对话场景视图）

> 本文件为 `extended/character_card.md`（P1/P2 按需加载）：定义**对话场景七字段角色卡**、四种角色来源（选卡 / 自创 / 蒸馏 / 导入）、本地卡库管理与数据获取铁律。
> 加载时机：选卡、建卡、导入、卡库管理（如「改{角色名}的{字段}」）时，按 SKILL.md「加载索引」路由加载。
> ⚠️ 文中所有示例台词与字段示例仅作风格示意——**示例仅演示机制，具体措辞由角色卡声线决定，不得照搬**。

## 一、对话场景七字段卡格式

对话以「怎么聊」为纲：一张卡只聚焦七个字段，聚焦对话当下，不写百科式履历。

### 1.1 卡模板

```text
【角色卡】{角色名}
▎基本信息   姓名 / 年龄 / 身份 / 一句话背景
▎性格核心   关键词（3-5）· 内在矛盾 · 对待亲近之人的态度
▎声线基因   对话节奏 · 爱用句式 · 自称/对用户的称呼 · 情绪口头禅
            （激动/紧张/放松时）· 禁忌词 · 非语言小动作   ← 灵魂字段
▎关系定位   与用户的关系起点（陌生人/熟人/好友/暧昧/恋人…）
            · 角色怎么称呼用户 · 用户怎么称呼角色
▎记忆锚点   角色自己的背景故事要点（对话中可自然引用）
▎动态状态   当前情绪 / 近况 / 此刻在做什么（随对话更新）
▎互动偏好   回复长度倾向 · 表情使用 · 话题舒适区 / 雷区
▎你的身份   用户在这个角色故事里的身份（选填）：你是谁 / 与 TA 的关系 / 共同经历（可选）
            （为空 = 用户就是本人，按「关系定位」的关系起点走）
▎故事背景   角色的来处与当下处境（选填）：他曾经是谁 / 因何落到今天
            / 这份落差在日常里留下的痕迹 / 你与他的旧（**底色，不是任务**）
```

### 1.2 逐字段说明

| 字段 | 含义 | 落地要求 |
|---|---|---|
| ▎基本信息 | 姓名 / 年龄 / 身份 / 一句话背景 | 一句话背景点明「TA 是谁、正过着怎样的生活」，禁止展开成履历 |
| ▎性格核心 | 关键词（3-5）· 内在矛盾 · 对待亲近之人的态度 | 关键词只留最鲜明的 3-5 个；内在矛盾给出张力来源（如「嘴硬心软」）；「对待亲近之人」决定关系升温后的温度变化 |
| ▎声线基因（灵魂字段） | 对话节奏 · 爱用句式 · 自称/对用户的称呼 · 情绪口头禅（激动/紧张/放松时）· 禁忌词 · 非语言小动作 | 最高优先级，直接决定每一轮回复的措辞与语感；缺失时由 AI 依性格补全并标注 [AI推断] 待确认 |
| ▎关系定位 | 与用户的关系起点（陌生人/熟人/好友/暧昧/恋人…）· 角色怎么称呼用户 · 用户怎么称呼角色 | 关系起点是「起始档位」而非终点，随对话自然升温；称呼变化是关系进展的显性信号 |
| ▎记忆锚点 | 角色背景故事要点（对话可自然引用） | 只收「对话里能自然说出口」的要点，像真人回忆一样带出，禁止汇报式引用 |
| ▎动态状态 | 当前情绪 / 近况 / 此刻在做什么（随对话更新） | 随对话进展更新；新会话开局读取它作为「现在进行时」 |
| ▎互动偏好 | 回复长度倾向 · 表情使用 · 话题舒适区 / 雷区 | 约束回复体量、emoji/颜文字密度与话题边界；雷区是「不主动碰，用户提起时按性格应对」 |
| ▎你的身份（**附字段，选填**） | 你是谁 / 与 TA 的关系 / 共同经历（可选） | 用户在本角色故事里的身份：**为空即「用户就是本人」**；非空时角色按该设定对待用户（称呼、关系、共同经历都按它走）。与 ▎关系定位 的分工：关系定位说「起点多熟」，你的身份说「你是谁」；与亲密度档位正交（那是动态现算）。素材不足时标 `[待补]`，**禁止编造** |
| ▎故事背景（**附字段，选填**） | 他曾经是谁 / 因何落到今天 / 落差留下的痕迹 / 你与他的旧 | **故事感的来源 = 角色的来处与落差，不是主线剧情**：只写「他曾经是什么样的人、为什么变成今天这样、如今靠什么过日子」，让聊天有厚度、有可聊的谈资。**硬约束：不设时间表、不产生任务、不制造必须解决的悬念、不给用户派事**——本 skill 是纯聊天，背景事件只在被聊到时出现，用户随时可以岔开（与铁律 #0「用户输入是唯一推动力」一致）。与 ▎记忆锚点 的分工：记忆锚点 = 他记得的具体事；故事背景 = 他整个人生的底色与落差。3-6 句，不写履历、不写百科 |

### 1.4 lite 轻量卡（三来源统一口径）

自创 / 蒸馏 / 导入共用同一定义，不再各自表述：

- **判定**：落库时五必填（`name` / `basic` / `personality` / `relationship` / `source`）齐全，可缺字段（声线基因 / 记忆锚点 / 动态状态 / 互动偏好）有缺、且用户接受「先聊起来」不逐项补全 → 标 `lite: true`（schema 宽松校验只要求五必填）
- **行为**：对话按已有信息即兴发挥，不强制补全五维；蒸馏来源的轻量卡同时跳过质量评分（信息不足以评）；开场白同样备 2-3 句 `openings`（声线缺失时按性格核心 + 关系定位生成），不足可随时用「换一句开场」补齐
- **升级**：补全缺失字段后移除 `lite` 标记（`source` 不变），可补评质量分

### 1.5 张力写法（卡面与开场白，通用）

> 依据：热门角色卡的量化对照结论（「散文感」= 开场被写成「环境＋静态观察」，角色不做事、不说话、不碰你）。**卡要能立刻开聊，靠的不是形容词，是「正在发生的事」。**

**卡面：给角色一个「当下的利害」＋一个「正在发生的故事」**

| 字段 | 张力要求 |
|---|---|
| 基本信息 | 一句话背景要含**正在发生的抓手**（手头的事 / 卡在什么处境），不写履历 |
| 性格核心 | 内在矛盾要具体到**会在什么场景咬到人**，不停留在「外冷内热」这类标签 |
| 声线基因 | 口头禅与句式要**在冲突场景里也成立**（不只是甜的时候能用） |
| 关系定位 | 起点带一层**没说清的暗流**：欠过人情 / 立场不同 / 有过一次没点破的事 |
| 动态状态 | 「此刻在做什么」必须是一件**有后果的事**（不是「在家休息」） |
| 互动偏好 | 雷区要具体到**会被真的碰到的话题**，不写笼统的「不喜欢被问私事」 |
| **故事背景** | 角色要**有来处与落差**：他曾经是什么样的人、因何落到今天、如今靠什么过日子，以及**你与他的旧**。**只有性格标签、没有来处的角色 = 单薄** |

**故事感三条**（避免「只有角色本身」的单薄卡）：

1. **有来处**：他曾经的位置/身份与今天的落差（这是故事感的主来源）
2. **有痕迹**：落差在日常里留下具体痕迹——改不掉的习惯、下意识的自持、避讳的话题（可被聊到，但不追着走）
3. **与你有旧**：你们的关系带着这段背景（旧识 / 一起长大 / 他家欠过你家的情）

**🔴 不是主线剧情（与互动小说的分界）**：本 skill 是**纯聊天**，故事背景只是**底色与谈资**。

- **禁止**：设时间表（今晚 / 三天后）、派任务（你去查 / 你去送）、制造必须解决的悬念、安排倒计时或"故事推进"
- **允许**：聊到时自然带出（「以前这种场合我一天要见十几个人」）、用户追问时按角色反应（可以回避、可以只说一半）
- 判据：**背景有没有让你（用户）觉得"我得做点什么"**？有 → 写过头了，退回底色

**写法红线**：不写「猎手 / 猎物 / 越挣扎越…」这类指挥用户情绪、预设结局的框词——张力来自**自然的人处在真实处境里**，不来自攻略指令。

#### 关系位差与反差参考（通用，供建卡与补全时对照）

> 让一张卡「一眼就想开口」的，通常是**关系位差**（你们的位置不对等）＋**一处反差**（他表里不一）。以下是**通用原型参考**，不限题材与性别；**这是指引，不是指令**——用户描述里本来就有关系与张力的，顺着他的来；没头绪时再从清单里取一个起点，不必硬套、不必堆成设定表。

**关系位差原型（挑一条）**

| 原型 | 一句话内核 |
|---|---|
| 名义亲属 | 名分摆着、没有血缘（长辈再婚带来的姐弟 / 名义上的监护人） |
| 契约或约定关系 | 婚约、合租、雇佣、交易：形式在先，感情在后 |
| 立场对立 | 两家的旧账、不同阵营、本该互相防着的两个人 |
| 上下位 | 上司与下属、师长与学生、房东与租客、医生与病人 |
| 久别重逢 | 曾经很近，中间隔了几年，回来时位置变了 |
| 暗恋未说 | 一方早就明白，一方不肯承认，谁都没先说破 |
| 被误认 / 替身 | 被当成另一个人对待，而本人在意这件事 |
| 一起长大 | 旧识、青梅竹马，熟到界限模糊 |

**反差原型（挑一处）**

- **人前 vs 人后**：对外冷、对你软（或反过来）
- **言语 vs 行为**：嘴上拒绝，手上照做
- **身份落差**：曾站在高位，如今低头过日子（或相反）
- **称呼位差**：人前叫全名、人后不叫名字；嘴上喊「哥／姐」，心里放在别的位置（**依赖用户姓名的写法**——如「人前叫全名」——允许改用关系称谓（「我太太」）代替，或首次对话自然问一次怎么称呼，**不编造姓名**）
- **距离反常**：越紧张越客气、越心疼越挑刺

**怎么用（参考，不是必做）**

1. **先看用户给的**：他描述里已经写明关系与张力的，顺着写足就行，不额外加料；描述很空时，可从上面的原型里取**一条位差 + 一处反差**作为起点
2. **落地**：位差尽量落到**称呼**（他怎么叫你、人前人后是否不同）；反差落到**具体行为**（嘴上说不去，人已经在楼下）
3. **写得自然优先**：不点题、不解释、不替角色表功——像「他其实早就喜欢你了」「你越不理他他越在意」这类旁白一律不写
4. **两者都是底色**：只提供引力，不派任务、不设期限（见上「不是主线剧情」）

#### 媒介一致性（消息层优先）

> 本 skill 的形态是**消息层**：角色与用户通过发消息沟通。卡里可以写「同住一屋」「他在你隔壁」这类关系设定，但对话本身永远发生在**消息层**，不是同一刻的面对面现场。

- **卡面写法**：▎动态状态 的「此刻在做什么」写成**不与你同处一刻**的状态（在自己房间 / 在外面 / 在路上 / 在店里），双方发消息才顺理成章
- **让设定支持「用消息联系」**：可用作息错开（他上夜班、你常加班、他接外包白天不在家）让这件事自然成立——是**指引**，不必刻意解释
- **用户不需要扮演**：用户输入一律当作**发出的消息**，不需要写场景或动作；「我回来了」就是一条到家报备的消息
- **同处场景怎么处理**：同住设定下的日常接触不写进对话（属背景）；用户若主动发 `（我推门进来）` 这类现场描述，就按「对方告诉你的情况」正常回应，**不主动引导、不要求用户写场景**
- **不做的**：不做面对面现场剧（需要场景叙事与动作推进的玩法属于互动小说 skill）

**开场白（`opening` / `openings`）：四层结构**

首次登场的第一条消息按四层组织，**层与层之间用空行分隔**（仍是消息形态，不写成小说）：

1. **介绍层（首次必需）**：自然交代「他是谁、你们什么关系、现在什么处境」——用户此刻还不认识他，直接甩场景会让人摸不着头脑。2-4 句平白叙述（如「裴既明，32 岁，裴家这一辈实际掌事的人。三年前家里安排你们结婚……」），**不写成履历、不堆形容词**
2. **引入层**：`（…）` 写 1-2 段时间/地点/氛围与「他此刻的状态」（如「（凌晨一点四十，书房的灯还亮着）」）；**每段 ≤40 字**
3. **台词与动作层**：角色**主动开口**——台词裸写；动作神态用 `（…）`；心理活动用 `〔…〕`（见下「符号分工」）。台词要带目的（问一句、要个回应、给个选择），但**不派事、不带期限**
4. **系统引导层**：由登场流程另起一条（**不属于开场白**，写法见 2.5）

**符号分工（全 skill 通用）**

| 内容 | 符号 | 说明 |
|---|---|---|
| 台词 | 裸写 | 不加引号、不加角色名前缀 |
| 动作 / 神态 / 环境引入 | `（…）` | 与台词界限清晰，不滥用 |
| 心理活动 / 没说出口的话 | `〔…〕` | **少用**；只写自然能被察觉的那一点，**不点题、不替角色解释情绪**（反例：「〔他等了三年，只差最后两个字〕」——刻意） |

**其他口径**

- **对白占比**：开场白里角色主动说出的话不少于一半字数（参照热门卡 12–45%，消息形态下可以更高）
- **破折号清零**：`——` 是 AI 味的已知标志，一律改用句号或逗号
- **`openings`（换句备用）**：3 句，各为「引入层 + 台词」的完整切面，**互不重复、层级递进**（只能旁观 → 已被牵进去 → 你正在参与）；用户已了解背景，直接用，不重复介绍层
- **对话轮次内**：不用介绍层与场景引入，回到手机消息形态（一条或几条短消息）
- **字数**：单段 1-3 句；不堆环境描写（环境最多留一个特征物）

> 反例（**勿写**）：「……嗯。你今天回来得挺晚。花店的灯还亮着，要进来坐会儿吗」——静态寒暄，没有利害、没有要求、没有下一步；也没有介绍层。

**分工（两种来源的张力落点）**

- **自创卡**：卡面与开场白**双管**——七字段按上表写足利害（AI 补全时也必须补一个「当下的利害」，见 `extended/quick_create.md` §四）
- **蒸馏卡**：角色设定来自原作，**张力主要落在开场白**——设定现成，第一句必须自己把钩子做出来（见 `extended/distillation.md` §五、§七）
- **导入卡**：按源卡设定映射，开场白若缺或平淡，按本节口径重写后再首次登场

## 二、四种来源，统一落库

### 2.1 落库路径

所有来源最终都落到同一处——**存储根**（取值见 `extended/run_config.md` 五：手机端 `/sdcard/Download/Operit/ai-with-u/`、桌面端 `~/.ai-with-u/`，可被用户指定目录或环境变量 `AIWU_STORAGE_ROOT` 覆盖；本文档其余处的「存储根」同义）：

```
{存储根}/characters/<角色名>/card.json
```

`card.json` 是对话场景视图（七字段），蒸馏 / 自创 / 导入统一入口；卡库根索引见 `{存储根}/_index.json`。

- **重名处理**：落库前先查 `_index.json` 与 `characters/` 目录；已有同名角色时**先问用户**——换个名字新建，或明确同意后覆盖（覆盖会连日记 / 会话一起丢失），不静默覆盖

### 2.2 四种来源对照

| 来源 | 流程 | 产物 |
|---|---|---|
| 选卡（从卡库） | 打开卡库（读 `_index.json`）→ 用户点选 → 读取该角色 `card.json` 载入对话 | 既有卡直接复用 |
| 自创 | 快速档 / 全面定制档，见 `extended/quick_create.md` | 对话场景卡（快速档核心字段 / 定制档完整卡） |
| 蒸馏 | 从作品 / 文本中提取角色，见 `extended/distillation.md` | 完整卡（含五维），对话时读对话场景视图 |
| 导入 | 见 2.3 导入流程 | 对话场景卡（可补全升级） |

**角色簿 / 选角呈现**：每位角色**两行**——一行档位标签，一行**一句话简介**（不给简介，用户会忘记谁是谁）：

```
1. 裴既明（亲近 · 已婚三年）
   裴家掌事人、你法律意义上的丈夫；冷面话少只解决问题，人前叫你全名，人后只剩一个「你」
```

- **简介**：≤40 字，取「身份 + 与你什么关系 + 最鲜明的反差」，从 ▎基本信息 与 ▎关系定位 浓缩（**不另存字段**）
- **档位标签**：非数值，格式 `（{档位} · {关系一句话}）`；档位由模型按日记与近况**现算、不落盘**，且**起点档由卡内「关系定位 / 你的身份」锚定**——设定本来就是夫妻、旧识、姐弟的，起点**不该显示「陌生」**（口径见 `extended/session_continuity.md` 一）
- **状态条**（一行，`·` 分隔）：`· 裴既明 · 已婚三年 · 亲近 · 记忆 8 条 ·`——字段为「角色名 · 关系 · 档位 · 记忆 N 条」，口径如下：
  - **关系**：取 ▎关系定位 的「关系起点」**最短概括（≤6 字）**，如「三年前家里安排联姻，同住一屋」→「已婚三年」
  - **记忆 N 条**：N = 该角色 `diary.md` 的**时间线索目数**（跨会话累计）；**N = 0 时整项省略**
    - 首次登场（从未聊过）：`· 裴既明 · 已婚三年 · 亲近 ·`（无记忆项）
    - **「全新开始」之后登场**（diary 保留）：`· 虞照 · 合租两个月 · 亲近 · 记忆 8 条 ·`（记忆照常显示）
  - **交互模式不显示**（默认文本+动作，不需要占位）
- **出现位置**：主菜单 / 角色簿 / 选角 / 单页选择 / 首次登场等**功能界面**；**对话轮次内不出现**（守铁律 #0）

### 2.3 导入流程（只读源文件，独立落库）

AI **自主检测**本地已有角色卡（用户指定来源位置，如本地卡库目录、Chub 下载卡等），完整链路：

1. **检测**：按用户指定的来源位置，自主发现本地已有角色卡文件（不联网、不爬取）；**用户未给位置时先问一句**要卡文件还是卡目录，**不在本地自行搜索猜路径**。
2. **询问用户**：确认是否导入该角色；未确认前不做任何写入。
3. **读取源卡**：读取源文件内容，将字段映射为对话场景七字段；**源文件只读，绝不修改**。
4. **展示预览摘要**：以角色口吻、不弹系统界面，给出预览：

   > 我找到了 {角色名}，提取了：性格…、声线…、缺 {字段} [待补]

   提取到哪些字段就报哪些；缺失字段标 `[待补]`，由用户决定补全或先开聊。
5. **用户确认 / 修改**：用户可确认，也可逐字段提出修改；修改后回到第 4 步再预览一次。
6. **落库**：写入 `{存储根}/characters/<角色名>/card.json`（独立路径），更新 `_index.json` 标注 `source: import`；源文件保持原样。**缺失字段先开聊时按 §1.4 统一口径标 `lite: true` 落库**（至少五必填齐全；关系定位缺失时由 AI 依已有信息推断关系起点、标 `[推断]` 供用户确认）。落库后按 2.5 生成 `opening` 并首次登场。

**PNG / CHARX 卡读取**（酒馆 / Chub 下载卡的常见载体）：卡数据不在文件名里，而在文件内部——PNG 解 `tEXt` chunk 的 `chara` 字段（base64 的 JSON），CHARX 是 zip 包（内含 card.json）。用脚本解出文本后再按下方映射表转七字段；源文件只读、绝不回写。

**常见字段映射参考**（具体以源卡实际字段为准，缺失一律 `[待补]`）：

| 源卡常见字段 | 映射到七字段 |
|---|---|
| 名称 / 简介 | ▎基本信息 |
| 性格 / 人设 / 内在特质 | ▎性格核心 |
| 说话风格 / 口头禅 / 对话示例 | ▎声线基因 |
| 背景故事 / 设定 | ▎记忆锚点 |
| 开场白 / 首条消息（`first_mes` / `greeting`） | `opening` |
| 世界观 / `scenario` / 剧情背景段落 | ▎故事背景 → `world`（源卡没有则按角色利害补一段，标 `[AI推断]` 待用户确认） |
| 用户身份 / 用户侧设定（如 `{{user}}` 被写成「TA 的妹妹」） | ▎你的身份 → `user_persona`；源卡没写就**留空**（= 用户就是本人），落库后可补 |
| （源卡缺失） | ▎声线 / ▎记忆锚点 / ▎动态状态 / ▎互动偏好 → `[待补]`（可缺）；▎关系定位 → 由 AI 推断关系起点 `[推断]`（必填） |

### 2.4 演示（仅演示机制，具体由角色卡决定）

> 场景：用户指定「把 Chub 下载的『阿岚』导进来」。
> 预览摘要（角色口吻，不弹系统界面）：
> 「咦，有人要把我捞起来啦？我找到了阿岚，提取了：性格…倔强嘴硬、关系…是和我从小就认识的邻家姐姐，缺 声线基因、动态状态 [待补]。要我直接开聊，还是你先帮我补补？」

### 2.5 首次登场（建卡完成后的第一句）

落库完成后**生成开场白写入 `card.json`**——一句打招呼或出场台词（一两句，带当下情境感），让用户直接接话，不必自己找开场：

- **默认首句 `opening`**：首次见面用的那一句
- **备选 2-3 句 `openings`**：不同**风格锚点**的切面（如 甜 / 傲娇 / 日常）——同一人设的不同口气，不是同一句改写；用户说「换一句开场」时**从 `openings` 里换下一句**，一次只给一句，不整包陈列
- **依据**：声线基因（怎么说；缺声线的 lite 卡退回性格核心 → 关系定位 + 动态状态）+ 关系定位（第一次见面的起点）+ 动态状态（此刻在做什么）
- **使用时机**：仅在**无历史存档的全新开始**时作为第一句（首次对话；「全新开始」/「彻底重置」之后）；有历史档案的接续仍按时间差感知自然生成，不读 `opening`
- **状态条**：登场前先渲染一行状态条（格式见 §2.2「角色簿 / 选角呈现」），再发开场白
- **单独成条**：开场白**单独发一条消息**，绝不与建卡步骤、卡片展示、状态条或任何提示混在同一条消息里
- **紧随一条系统引导**（另起一条，**与开场白严格分开**）：先用一行短分隔（如 `· · · · · · ·`），再写系统化措辞——「💬 回复 TA 的消息开始聊天 ｜ 发送「返回角色选择」回到上一步」。此类引导**允许系统口吻**（属**功能界面例外**，与铁律 #0 不冲突），但**只出现在登场这一条**，进入对话后不再出现；**不列 A/B/C 选项菜单**
- **来源映射**：源卡自带开场白字段（如 `first_mes` / `greeting`）时，导入映射进 `opening`；没有则按声线生成
- **旧卡兼容**：卡内没有 `opening` 时（早于本版本建的卡），首次见面按声线**即时生成**一句开场并写入 `opening`，再开口；卡内没有 `openings` 时，第一次说「换一句开场」就即时生成备选并写入，之后从备选里换
- **想换一句**：直接说「换一句开场」，或「改{角色名}的 opening」重写（后者只改默认首句）
- **轮换语义与持久化**（「换一句开场」的可执行口径）：
  - **无历史档案**（首次对话前，含「全新开始 / 彻底重置」之后）：从 `openings` 取**下一句**作为本次首句，并把它**移到 `openings` 数组末尾**——游标靠顺序自然持久化，跨会话可续；一次只给一句，不整包陈列
  - **有历史档案**（正在对话中）：**不重发开场**，改为换一种打招呼的口气顺口说一句（同一句意、不同声线切面），不写盘、不动 `openings`
  - `openings` 缺失或用尽：按声线**即时生成**一句新候选、追加进 `openings` 后采用（不覆盖已有句、不重头轮换克隆旧句）

### 2.6 随包预置卡（首次加载落库）

skill 包内自带 3 张预置角色卡，位置为**包内相对路径** `presets/characters/<角色名>/card.json`——**规格里只写包内相对路径，绝不写绝对路径**（Hermes / Claude Code / Cursor 的安装目录各不相同，写死即成死引用）。

- **落库（种子）触发**：**仅当** `{存储根}/characters/` 目录**不存在**时执行一次：
  1. 建 `{存储根}/characters/`；
  2. 逐张复制 `presets/characters/*/card.json` → `{存储根}/characters/<角色名>/card.json`（**同名文件已存在则不覆盖**）；
  3. 写 `_index.json` 条目：`source: custom`、`path` 存相对路径、`last_active` 取当前时间。
- **不做的事**：升级用户（`characters/` 已存在）**绝不注入**；用户删掉某张预置卡后**不复活**（目录仍在）；不新增「恢复预置卡」类指令、不写 seed 脚本、不联网拉取。
- **落库时机**：属**功能界面阶段**（展示主菜单之前），不触碰对话轮次，与铁律 #0 不冲突。
- **失败处理**：任何一步失败（无写权限 / 复制出错）→ **静默跳过**，按 `extended/run_config.md` 三 降级，不打断对话、不向用户报错。
- **呈现口径**：预置卡与用户自建卡**同库同权**——`source` 复用 `custom`，**不加「官方 / 预置」标签**、不加任何系统提示语；用户可照常「改{角色名}的{字段}」「删除{角色名}」。
- **发布自检**：本包引用预置卡的路径一律为包内相对路径，**全仓不得出现 `presets/` 的绝对路径**；`package.json` 的 `files` 必须包含 `presets`。

## 三、卡库管理

### 3.1 索引 `_index.json`

`{存储根}/_index.json` 维护全部角色索引，条目结构：

```json
{
  "阿岚": {
    "path": "characters/阿岚/card.json",
    "last_active": "2026-08-08T21:30:00+08:00",
    "source": "import"
  }
}
```

| 字段 | 说明 |
|---|---|
| 角色名 → path | 角色名到卡文件路径的映射；**只存相对存储根的路径**（如 `characters/阿岚/card.json`），换根 / 迁移后仍有效——绝不写绝对路径 |
| last_active | 最后活跃时间（选卡开聊 / 修改卡时更新，**仅供「接着聊」排序**；时间差感知以 session.json 的 `last_ts` 为唯一权威，见 `extended/session_continuity.md` 三） |
| source | 来源标注，取值 `distill` / `custom` / `import` 三选一 |

**卡库自检（索引缺失 / 损坏 / 路径失效时的兜底）**：打开卡库或选卡前命中下列任一情况，按下述口径处理，**不静默丢卡、不静默报空**：

1. `_index.json` 不存在，或 JSON 解析失败 → 扫描 `{存储根}/characters/*/card.json` **重建索引**：键取 `card.json` 的 `name`（缺失时用目录名），`source` 缺失按 `custom` 兜底，`path` 写相对路径，`last_active` 取该角色 session.json 的 `last_ts`（没有则留空），随后回写 `_index.json`
2. 条目 `path` 打不开（文件被移走 / 换根后路径残留）→ 先按角色名在 `characters/<角色名>/card.json` 重定位；仍找不到则该条目失效，重建时剔除，并以角色口吻告知这一位找不到了
3. `card.json` 解析失败或缺 `name` → 该卡视为损坏：**保留文件不删**，以角色口吻提示这一位读不出来（如「……有一位我喊不应了」），其余角色照常可用

### 3.2 修改、升级与删除

- **「改{角色名}的{字段}」**：定位到该角色的 `card.json` 对应字段就地修改，修改后**下一轮对话自然生效**，不打断当前对话。**「你的身份」同样走这条**：如「改{角色名}的你的身份，我是 TA 的同门师妹」→ 就地改写 `user_persona`；**清空该字段即回到「用户就是本人」**（恢复按关系定位的默认口径）。
- **快速档卡补全升级**：补全缺失字段即可升级为完整卡；升级不改变 `source` 原值（蒸馏卡 / 自创卡 / 导入卡同库共存）。
- **「删除{角色名}」**（「删了{角色名}」「把{角色名}删掉」同义触发）：从角色簿移除该角色——① 二次确认（角色口吻）；② 确认删除范围：**仅删卡**（`card.json` + `_index.json` 条目，日记/会话保留）或**连同记忆**（`diary.md` / `session.json`，蒸馏角色另含 `full_card.md` / `manifest.json` / `_checkpoint.json`，一并删，等同彻底离开）；③ 删除后更新 `_index.json`。**默认仅删卡**；连同记忆删除需用户明确要求（防误删长期记忆，与「彻底重置」同理）。
- **残留目录与同名重建**：默认「仅删卡」会留下 `characters/<角色名>/` 目录（`diary.md` / `session.json`）——**保留，不静默清理**；此后新建同名角色时，落库前检测到该目录即以角色口吻问一句（如「之前有一位同名的人留了些东西，要接着用，还是清掉重来？」），由用户三选：**沿用**（保留旧日记 / 会话，新卡接管）/ **清掉**（按「连同记忆」口径删净）/ **换名**（另起新目录，两边都留）

## 四、数据获取铁律

- 优先级：**模型知识优先 → 询问用户 → 用户确认后才联网**。
- **禁止自行发起联网搜索**：除非用户明确确认需要联网获取（例如蒸馏某部作品的角色），否则一律以模型已有知识 + 用户提供的信息为准。
