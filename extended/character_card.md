# AI-WITH-U · 角色卡体系（对话场景视图）

> 本文件为 `extended/character_card.md`（P1/P2 按需加载）：定义**对话场景七字段角色卡**、四种角色来源（选卡 / 自创 / 蒸馏 / 导入）、本地卡库管理与数据获取铁律。
> 加载时机：选卡、建卡、导入、卡库管理（如「改{角色名}的{字段}」）时，按 SKILL.md「加载索引」路由加载。
> ⚠️ 文中所有示例台词与字段示例仅作风格示意——**示例仅演示机制，具体措辞由角色卡声线决定，不得照搬**。

## 一、对话场景七字段卡格式

对话以「怎么聊」为纲：一张卡只聚焦七个字段，聚焦对话当下，不写百科式履历。

### 1.1 卡模板

```text
【角色卡】{角色名}
▎基本信息   姓名 / 年龄 / 身份 / 一句话背景
▎性格核心   关键词（3-5）· 内在矛盾 · 对待亲近之人的态度
▎声线基因   对话节奏 · 爱用句式 · 自称/对用户的称呼 · 情绪口头禅
            （激动/紧张/放松时）· 禁忌词 · 非语言小动作   ← 灵魂字段
▎关系定位   与用户的关系起点（陌生人/熟人/好友/暧昧/恋人…）
            · 角色怎么称呼用户 · 用户怎么称呼角色
▎记忆锚点   角色自己的背景故事要点（对话中可自然引用）
▎动态状态   当前情绪 / 近况 / 此刻在做什么（随对话更新）
▎互动偏好   回复长度倾向 · 表情使用 · 话题舒适区 / 雷区
```

### 1.2 逐字段说明

| 字段 | 含义 | 落地要求 |
|---|---|---|
| ▎基本信息 | 姓名 / 年龄 / 身份 / 一句话背景 | 一句话背景点明「TA 是谁、正过着怎样的生活」，禁止展开成履历 |
| ▎性格核心 | 关键词（3-5）· 内在矛盾 · 对待亲近之人的态度 | 关键词只留最鲜明的 3-5 个；内在矛盾给出张力来源（如「嘴硬心软」）；「对待亲近之人」决定关系升温后的温度变化 |
| ▎声线基因（灵魂字段） | 对话节奏 · 爱用句式 · 自称/对用户的称呼 · 情绪口头禅（激动/紧张/放松时）· 禁忌词 · 非语言小动作 | 最高优先级，直接决定每一轮回复的措辞与语感；缺失时由 AI 依性格补全并标注 [AI推断] 待确认 |
| ▎关系定位 | 与用户的关系起点（陌生人/熟人/好友/暧昧/恋人…）· 角色怎么称呼用户 · 用户怎么称呼角色 | 关系起点是「起始档位」而非终点，随对话自然升温；称呼变化是关系进展的显性信号 |
| ▎记忆锚点 | 角色背景故事要点（对话可自然引用） | 只收「对话里能自然说出口」的要点，像真人回忆一样带出，禁止汇报式引用 |
| ▎动态状态 | 当前情绪 / 近况 / 此刻在做什么（随对话更新） | 随对话进展更新；新会话开局读取它作为「现在进行时」 |
| ▎互动偏好 | 回复长度倾向 · 表情使用 · 话题舒适区 / 雷区 | 约束回复体量、emoji/颜文字密度与话题边界；雷区是「不主动碰，用户提起时按性格应对」 |

### 1.3 字段键映射（七字段 ↔ card.json ↔ 蒸馏五维）

| 对话场景七字段（中文区块） | card.json 键 | 蒸馏五维来源 |
|---|---|---|
| 基本信息 | basic | profile |
| 性格核心 | personality | personality |
| 声线基因 | voice | interaction（展开） |
| 关系定位 | relationship | relations |
| 记忆锚点 | memory_anchor | memory |
| 动态状态 | dynamic_state | 运行时状态（不来自五维，随对话更新） |
| 互动偏好 | interaction_pref | interaction / 运行时补 |

## 二、四种来源，统一落库

### 2.1 落库路径

所有来源最终都落到同一处（存储根目录 `~/.ai-with-u/` 可由环境变量 `AIWU_STORAGE_ROOT` 覆盖）：

```
~/.ai-with-u/characters/<角色名>/card.json
```

`card.json` 是对话场景视图（七字段），蒸馏 / 自创 / 导入统一入口；卡库根索引见 `~/.ai-with-u/_index.json`。

### 2.2 四种来源对照

| 来源 | 流程 | 产物 |
|---|---|---|
| 选卡（从卡库） | 打开卡库（读 `_index.json`）→ 用户点选 → 读取该角色 `card.json` 载入对话 | 既有卡直接复用 |
| 自创 | 快速档 / 全面定制档，见 `extended/quick_create.md` | 对话场景卡（快速档核心字段 / 定制档完整卡） |
| 蒸馏 | 从作品 / 文本中提取角色，见 `extended/distillation.md` | 完整卡（含五维），对话时读对话场景视图 |
| 导入 | 见 2.3 导入流程 | 对话场景卡（可补全升级） |

### 2.3 导入流程（只读源文件，独立落库）

AI **自主检测**本地已有角色卡（用户指定来源位置，如互动小说通用卡库、Chub 下载卡等），完整链路：

1. **检测**：按用户指定的来源位置，自主发现本地已有角色卡文件（不联网、不爬取）。
2. **询问用户**：确认是否导入该角色；未确认前不做任何写入。
3. **读取源卡**：读取源文件内容，将字段映射为对话场景七字段；**源文件只读，绝不修改**。
4. **展示预览摘要**：以角色口吻、不弹系统界面，给出预览：

   > 我找到了 {角色名}，提取了：性格…、声线…、缺 {字段} [待补]

   提取到哪些字段就报哪些；缺失字段标 `[待补]`，由用户决定补全或先开聊。
5. **用户确认 / 修改**：用户可确认，也可逐字段提出修改；修改后回到第 4 步再预览一次。
6. **落库**：写入 `~/.ai-with-u/characters/<角色名>/card.json`（独立路径），更新 `_index.json` 标注 `source: import`；源文件保持原样。

**常见字段映射参考**（具体以源卡实际字段为准，缺失一律 `[待补]`）：

| 源卡常见字段 | 映射到七字段 |
|---|---|
| 名称 / 简介 | ▎基本信息 |
| 性格 / 人设 / 内在特质 | ▎性格核心 |
| 说话风格 / 口头禅 / 对话示例 | ▎声线基因 |
| 背景故事 / 设定 | ▎记忆锚点 |
| （源卡缺失） | ▎关系定位 / ▎动态状态 / ▎互动偏好 → `[待补]` |

### 2.4 演示（仅演示机制，具体由角色卡决定）

> 场景：用户指定「把 Chub 下载的『阿岚』导进来」。
> 预览摘要（角色口吻，不弹系统界面）：
> 「咦，有人要把我捞起来啦？我找到了阿岚，提取了：性格…倔强嘴硬、声线…话不多但带刺，缺 关系定位、动态状态 [待补]。要我直接开聊，还是你先帮我补补？」

## 三、卡库管理

### 3.1 索引 `_index.json`

`~/.ai-with-u/_index.json` 维护全部角色索引，条目结构：

```json
{
  "阿岚": {
    "path": "~/.ai-with-u/characters/阿岚/card.json",
    "last_active": "2026-08-08T21:30:00+08:00",
    "source": "import"
  }
}
```

| 字段 | 说明 |
|---|---|
| 角色名 → path | 角色名到卡文件路径的映射 |
| last_active | 最后活跃时间（选卡开聊 / 修改卡时更新，供「接着聊」排序与时间差感知参考） |
| source | 来源标注，取值 `distill` / `custom` / `import` 三选一 |

### 3.2 修改与升级

- **「改{角色名}的{字段}」**：定位到该角色的 `card.json` 对应字段就地修改，修改后**下一轮对话自然生效**，不打断当前对话。
- **快速档卡补全升级**：补全缺失字段即可升级为完整卡；升级不改变 `source` 原值（蒸馏卡 / 自创卡 / 导入卡同库共存）。

## 四、数据获取铁律

- 优先级：**模型知识优先 → 询问用户 → 用户确认后才联网**。
- **禁止自行发起联网搜索**：除非用户明确确认需要联网获取（例如蒸馏某部作品的角色），否则一律以模型已有知识 + 用户提供的信息为准。
